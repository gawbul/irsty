# Packaging and releases

Irsty is released as archives on GitHub, built by [dist](https://opensource.axo.dev/cargo-dist/). Nothing is published to crates.io: every crate has `publish = false`.

## What a release contains

For each of `aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` and `x86_64-pc-windows-msvc`, an archive (`.tar.xz`, or `.zip` on Windows) with a SHA-256 checksum, holding:

- `irsty` (or `irsty.exe`)
- `irsty.1`, the man page
- `completions/`: `irsty.bash`, `_irsty` (zsh), `irsty.fish`, `_irsty.ps1` (PowerShell) and `irsty.elv` (Elvish)
- `README.md`, `LICENSE` and `CHANGELOG.md`

There are also installer scripts (`irsty-installer.sh` and `irsty-installer.ps1`, which put `irsty` in `~/.cargo/bin`), `sha256.sum` for every file, and the source tarball.

`dist plan` lists all of this without building anything.

## Man page and completions

`irsty --man` prints the man page, and `irsty --completions <bash|zsh|fish|powershell|elvish>` prints completions. Both are generated from the command-line definition (`crates/irsty/src/assets.rs`), so they always match the flags. Copies are kept in `assets/` for packagers, so building from source never needs a working `irsty` first. A test fails if they are out of date; `mise run assets` regenerates them.

| File | Install as |
|---|---|
| `assets/man/irsty.1` | `man1/irsty.1` |
| `assets/completions/irsty.bash` | `bash-completion/completions/irsty` |
| `assets/completions/_irsty` | `zsh/site-functions/_irsty` |
| `assets/completions/irsty.fish` | `fish/vendor_completions.d/irsty.fish` |

## Releasing

Releases are cut by pushing a version tag; the `Release` workflow (`.github/workflows/release.yml`, generated by dist) builds every archive and creates the GitHub release. On pull requests the same workflow only runs `dist plan`, as a check.

1. Start from an up-to-date `main`, on a release branch.
2. Set `version` in `[workspace.package]` in `Cargo.toml`.
3. Move the `[Unreleased]` section of `CHANGELOG.md` under the new version and date.
4. Set `MAN_DATE` in `crates/irsty/src/assets.rs` to the release date, then `mise run assets`.
5. `./scripts/gate.sh`, then `mise exec -- dist plan` to check the release looks right.
6. Merge, then tag the merge commit and push the tag: `git tag v0.2.0 && git push origin v0.2.0`.

dist itself is pinned in `mise.toml`. After changing `dist-workspace.toml` (or upgrading dist), run `mise exec -- dist generate` to regenerate the workflow; never edit `release.yml` by hand, or the check fails.

## Distribution packages

`packaging/` has starting points for three package managers. Each builds from a release's source tarball, installs the binary, the man page and the bash, zsh and fish completions, and needs a release tag to point at. Building needs Rust and a C and C++ compiler (for the bundled SQLite and Luau); there are no other system libraries to link.

| Package manager | Template | Status |
|---|---|---|
| Homebrew | `packaging/homebrew/irsty.rb` | Passes `brew style`; not yet installed from a tap. Put it in a tap (such as `gawbul/homebrew-tap`) as `Formula/irsty.rb`, set `url` and `sha256` for the release, and `brew install gawbul/tap/irsty`. Its test checks `--version` and that `--print-default-config` passes `--check-config`. |
| AUR (Arch Linux) | `packaging/aur/PKGBUILD` | Untested (no Arch machine here). Set `pkgver`, run `updpkgsums`, check with `namcap`, and publish to the AUR as `irsty`. It runs the `irsty-proto` tests, which need no network. |
| Nix | `packaging/nix/package.nix` | Untested (no Nix here). Use with `callPackage`; build once with the fake hashes and copy the real ones from the error. |

The full test suite starts mock servers on localhost, which some build sandboxes forbid, so the templates run the protocol tests only.
